# Enable Subagent

把用户明确给出的例外绑定到当前功能，跨该功能的后续对话保留，完成后恢复默认规则。
调用本 skill 本身即表示用户允许为当前功能使用 subagent；只读到本文件或由 agent 自动选中
skill，不产生授权。

## 确定边界

1. 从用户本次调用或当前任务上下文确定功能目标。已有任务计划时，将功能范围和这次授权
   记入该计划；没有计划时保留在会话上下文，不为一个执行偏好另建计划。
2. 用户的这次明确指令可以覆盖同层级 `AGENTS.md` 中的默认禁用规则。系统或开发者层级
   的限制、工具权限以及与 subagent 无关的规则继续生效。边界不清且无法从上下文确定时，
   只问缺失的功能范围；范围已明确时直接继续，不重复请求许可。
3. 简短告知用户例外覆盖哪个功能。保持 `AGENTS.md`、全局配置和其他功能的默认规则原样。

## 使用例外

- 按任务需要决定是否委派。用当前平台的原生 subagent 工具，明确每个任务的职责、可写
  文件、产物和验证要求；当前 agent 负责整合与最终验证。
- 多个 agent 共用工作树时告知它们保留他人改动，安排互不重叠的写入归属。例外不许可
  额外的 worktree、CLI 后台 agent 或外部消息发送。
- 后续消息、上下文压缩或同一功能的继续执行不撤销授权。相邻任务、另一个功能或另一个
  会话不会仅因本功能获准而继承例外。

## 结束例外

用户撤销、取消该功能或功能完成时，停止本功能仍在运行的 subagent，整合已产出的结果，
并将当前功能的授权状态记为已结束。撤销 subagent 授权本身不等于取消功能：由当前 agent 继续
剩余工作。之后按仓库默认规则执行；扩展到另一功能需要用户明确授权。
