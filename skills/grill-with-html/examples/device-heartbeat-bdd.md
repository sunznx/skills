## 设备与心跳

**系统与角色**：设备管理负责保存记录和管理运行实例。管理员使用 Admin 或 Lab CLI；Stats 接收心跳。运行时和中继分别提供实例与连接观测。

**测试数据**：在隔离测试环境建立国内设备 `D1` 和同区对照设备 `D2`。记录设备 ID、实例 ID 和本轮标识。心跳场景记录配置的心跳周期 `T` 与 Stats 当前游标。以下只定义计划，无目标 Lab 实跑证据。`2T` 是建议的测试窗口，不是生产承诺。

### 状态索引

```state LR
已关机 -> 启动中: 开机
启动中 -> 运行中: 实例就绪
运行中 -> 失败: 实例意外退出
失败 -> 启动中: 手动重试
运行中 -> 停止中: 关机
停止中 -> 已关机: 停止确认
已关机 -> [*]: 确认删除
```

```state LR
正常上报 -> 暂停上报: 暂停心跳
暂停上报 -> 正常上报: 恢复心跳
```

状态图索引本例覆盖的转换。接口字段由实际 `api` 契约维护；本例不假定接口路径。

### 正常行为

#### D01 开机后关窗不关机

- **Given**：Admin 选国内。`D1` 已建档、已关机，运行时没有 `D1` 的实例。
- **When**：管理员从 Admin 开机；实例就绪后关闭浏览器窗口。
- **Then**：
  - 用 Lab CLI 按 `D1` 回读。记录仍在国内，海外列表没有 `D1`。
  - 关闭窗口前后，本轮的运行时查询都只返回一个存活实例。两次实例 ID 相同。
- **验证入口**：Admin 设备详情、Lab CLI 双区回读、Docker 或 Kind 按设备与本轮标识查询实例。
- **证据 · 待执行**：保留关窗前后实例快照和双区查询结果。

#### D02 暂停只影响心跳

- **Given**：`D1` 在运行。Stats 已收到该实例的定时心跳。若验收包含中继，先建立一条独立连接并记录连接 ID。
- **When**：管理员暂停 `D1` 的心跳，不执行关机。
- **Then**：
  - 暂停确认后，先核对在途心跳已结清并记录 Stats 游标。接下来的 `2T` 内，游标后没有该实例的新心跳。
  - 同一运行时实例仍存活。若验收包含中继，探针仍通过原连接收发数据，无须重连。
- **验证入口**：Admin 暂停回执、Stats 游标回读、运行时查询。中继纳入范围时，另取既有连接的两端记录。
- **证据 · 待执行**：保留对时回执、Stats 查询、实例快照和约定范围内的连接探针结果。

#### D03 恢复触发首次上报

- **Given**：`D1` 仍用原实例运行，心跳已暂停。记录 Stats 游标和下一次周期发送的时间点；用测试时钟隔开手动恢复与周期发送。
- **When**：管理员恢复 `D1` 的心跳。
- **Then**：
  - 在下一次周期发送之前，Stats 在原游标之后收到同一实例的一条新心跳。该时间窗只新增一条。
  - 推进测试时钟到下一周期。Stats 收到下一条心跳；运行时实例 ID 未变。
- **验证入口**：恢复回执、测试时钟、Stats 游标与运行时查询。没有可控时钟时，先确认等效的观察窗。
- **证据 · 待执行**：保留恢复回执、首条与下一周期事件的时间及实例 ID。可用观察窗待确认。

### 失败与恢复

#### D04 实例异常退出可见

- **Given**：`D1` 和 `D2` 运行中。用实例 ID 确认本轮故障只作用于 `D1`。
- **When**：在测试环境让 `D1` 的实例意外退出，不发出管理端关机请求。
- **Then**：
  - 运行时确认原实例已退出。管理端在约定观测窗口内将同一个 `D1` 标为失败，而不是已关机。
  - `D2` 的实例 ID 与存活状态保持不变。
- **验证入口**：测试环境的故障注入点、运行时退出结果、Admin 设备回读。先确认失败可见的观察时限。
- **证据 · 待执行**：保留退出记录、设备查询与对照快照。观测时限待确认。

#### D05 手动重试复用设备记录

- **Given**：`D1` 保留同一设备 ID，处于失败状态，旧实例已退出。移除测试故障，保留旧实例 ID 作为基线。
- **When**：管理员对 `D1` 发起一次手动重试。
- **Then**：
  - Admin 和 Lab CLI 回读同一个 `D1`，没有新增设备记录。
  - 本轮只有一个存活实例，其 ID 不同于旧实例。运行时就绪后，`D1` 才显示运行中。
- **验证入口**：Admin 重试、Lab CLI 记录查询、运行时实例查询与就绪记录。
- **证据 · 待执行**：保留重试回执、设备列表差异和新旧实例 ID。

### 关停与清理

#### D06 关机回收实例，保留设备

- **Given**：`D1` 运行中；记录其设备和实例 ID。`D2` 仍在运行，作为对照。
- **When**：管理员对 `D1` 发出关机请求。
- **Then**：
  - 管理端显示已关机时，运行时已确认 `D1` 的实例退出。按本轮标识查不到它的运行实例。
  - Lab CLI 仍能查到同一个 `D1`；`D2` 的实例 ID 和存活状态未变。
- **验证入口**：Admin 关机、运行时停止记录和实例查询、Lab CLI 设备回读。
- **证据 · 待执行**：保留停止与状态变更时间、设备回读和对照实例快照。

#### D07 删除只清理本轮资源

- **Given**：`D1` 已关机、仍可查。列出归属本轮 `D1` 的应清理资源，以及不得删除的 `D2` 对照资源。
- **When**：管理员确认删除 `D1` 的设备记录。
- **Then**：
  - Admin 与 Lab CLI 都按原 ID 查不到 `D1`。资源清单中应清理的项目无残留。
  - `D2` 仍可回读；对照资源的 ID 和状态不变。
- **验证入口**：Admin 删除确认、双端回读、按本轮归属查询资源。先确认应清理资源清单。
- **证据 · 待执行**：保留删除回执、前后资源清单和 `D2` 快照。

### 证据边界

Cloud 原审阅稿提到本机 Docker 或 Kind 生命周期证据，以及 `managed-simulator` 的 Stats 与实例保持观察。本示例未复核原始回执。它们不等于目标 Lab 通过，也不能替代对原中继连接连续性的独立验证。
